# Color Filter Scheduler — UI redesign evidence

The presentation layer was rebuilt from first principles in the captain's
preferred "Left" menu-bar design language: a **custom dark rounded popover**
(SwiftUI hosted in an `NSPopover`), not the old stock gray `NSMenu`. The
scheduling engine (MediaAccessibility toggle + intensity, pure-Swift solar
math, reconcile timer, wake-reconcile, config persistence) is **unchanged**.

## Front panel — only what he asked for
`panel-front-running.png` / `panel-front-paused.png`

Header (day/night glyph + **Color Filter** + a muted status line + a settings
pill), one primary **Run / Pause** control, and a **Location** row. Nothing
else — no dead "Color Filter Scheduler" label, no "Reconcile Now", no exposed
lat/long fields.

- **Run** = turn Color Filters **ON** live (screen visibly changes).
- **Pause** = turn them **OFF** live.

## Settings — only what he asked for
`panel-settings.png`

**Strength** (real 0–100% intensity), **Location** lat/long fine-tune,
**Automatic (sunset → sunrise)** toggle, and **Quit**. Reached via the header
pill; a back chevron returns to the front.

## Menu-bar icon
`menubar-icon-light-dark.png`

A custom monochrome **template** glyph (ring with a half-filled disc = a color
filter / day–night split), drawn programmatically. Shown on a dark bar (renders
white) and a light bar (renders black) to prove `isTemplate` correctness. A
matching colored `.icns` bundle icon is generated by `tools/make-appicon.swift`
during `./bundle.sh`.

## Manual Run/Pause vs. Automatic — the rule
- **Automatic OFF (default):** the filter follows **only** the manual Run/Pause
  button; the reconcile timer is inert, so nothing moves the filter behind your
  back.
- **Automatic ON:** the solar scheduler owns the filter. Turning it on
  reconciles immediately. A manual Run/Pause while Automatic is on is a
  **temporary override** — the next reconcile (timer / wake / next
  sunrise–sunset transition) pulls it back to the schedule.

## Wired to the real engine (verified live, then restored)
Run/Pause and Strength call the same `ColorFilters` setters the headless CLI
uses. Demonstrated live and restored to exactly the state found at start:

| step | `--get` result |
|------|----------------|
| **BEFORE** (captain's state) | `enabled=false  type=16  strength=0.896634` |
| Run (`setEnabled true`)      | `enabled=true` |
| Strength (`intensity 0.50`)  | `strength=0.500000` |
| Pause (`setEnabled false`)   | `enabled=false` |
| restore strength             | `strength=0.896634` |
| **AFTER** (matches BEFORE)   | `enabled=false  type=16  strength=0.896634` |

Bundled app launched briefly under a self-kill wrapper: logged
`menu-bar item created`, ran, and exited cleanly with the captain's Color
Filters untouched. The app was **not** installed and no login item was
registered (firstmate handles the live reinstall).
